元冰可控制台 · 微信生态式交互重设计

现状是 19 个导航入口、5 个分区、11 个业务页面，每个页面开场先讲一段「什么是 X」， 用户要在一堆概念里自己拼出心智模型。新版把一级导航砍到 5 项、按「谁来用、在哪用」重排， 交互语言换成微信生态那一套：列表即卡片、点开是半屏、轻操作上滑、状态浅底深字。 功能一个不丢，只是从菜单里搬到了该在的位置。

先说病根：不是不好看，是概念太多

现有界面每页都做得挺完整，但用户拿到手要跨过三道坎才够得着事： 分区名要背（「治理与运营」和「组织」的分界在哪）、概念要认（连接器和三方集成到底什么关系）、 目标要翻译（「我想看看这个 Agent 谁在用」要先想该点哪个菜单）。

概念撞车

两个「连接器」

侧边栏同时有「连接器」（给 Agent 用的 SaaS 工具目录）和「三方集成」（组织身份同步）， 都归在不同的分区、不同的图标，但用户心智里这就是一件事——「接一个外部系统」。

连接器 · 1,000+ SaaS Provider 的数据面纳管
三方集成 · 组织账号的三方身份同步
层级打架

「工作台」和「部门面板」并列

这俩根本不是一类东西：工作台是管理员的控制台，部门面板是给业务同学的独立 SPA。 放在同一个导航里，用户点之前要先判断自己「是谁」，这个判断本该由登录身份自动完成。

侧边栏总览 → 工作台 / 部门面板

交互语言：微信生态的六条规矩

不是抄皮，是抄那套被十亿人验证过的信息密度和操作成本分配。

📋

列表即卡片，字段少而准

一个列表项只回答「这是什么 / 现在什么状态 / 我该点什么」。详情一律点开看，不在列表里堆指标。

现状：卡片里塞调用数、成功率、P95 延迟，一行六个信息点，看不出主次。
👆

点开是半屏，不是新页面

查看和轻编辑走底部升起的半屏面板（微信半屏菜单范式），关闭后回到原位置、滚动位置不变。 只有真正换了个任务才整页跳。

现状：看一个 Agent 要跳页 → 看完 → 再点浏览器返回找刚才的位置。
↥

轻操作上滑，高危才拦

切换、筛选、启停这类轻操作用顶部胶囊即时反馈（Toast），不打断。 只有删除/吊销这类不可逆的才用动作面板或居中确认，且危险项永远是红字。

现状：每次操作都弹居中 Modal，按钮还常常是灰的（disabled 状态）。
🏷️

状态是浅底深字的小胶囊

微信从不用实心彩色标签。绿=通过/在线、红=失败/待办、橙=需要注意、灰=未开始。 颜色只做辅助，文字才是真正的信息。

现状：开发中/已上线/已下线混用实心色块、描边、灰底三四种视觉方案。
🔍

一个搜索框管所有

⌘K 常驻，搜资源、搜人、搜订单、搜指令，不区分对象类型。 分区再多也不影响搜索——这是菜单可以砍的前提。

现状：⌘K 存在但覆盖不完整，用户仍需逐页找。
🎨

少色、少渐变、少阴影

底色 #F2F3F5，卡片纯白，只用 1px #EAEAEA 分隔。主蓝 #0052D9 只出现在主操作按钮上， 微信绿只用在通过态。大面积渐变全部取消。

现状：品牌渐变铺卡片头、hero 区、图标底，信息层级靠颜色堆而不是靠留白。

落地路径

前端是零构建原生 ES 模块，不需要重写框架。真正的成本在「一个页面拆成半屏 + 标签页」 这类结构调整，以及把现有页面的空态文案改掉。建议分三步走，每步都能独立上线。

1

只换壳，不动逻辑

新增 token 层与卡片列表组件，把 app.js 的 NAV 收敛成 5 项，旧页面全部挂到半屏容器里。 路由和 API 调用零改动，纯前端呈现层重构，风险最低，先把导航密度降下来。

2

拆页与合并

assets+finops 合并为「用量」、agents+apps+mcp+skills+nas 合并为「资源」、iam 三 tab 合并为「组织」， connectors 与 iam?tab=connectors 合并为「接入」。这一阶段要调后端聚合接口， 列表从「各查各的」改成一次拿齐。

3

填真实内容

现状最大问题不是结构是数据——工作台四个 KPI 全零。新版把「今天该我做什么」放在第一屏， 即使没数据也要给出原因和下一步动作。顺带删掉四个页面的「初次了解」弹窗， 这些内容收进空状态和帮助入口。

需要你拍板的两件事： ① 部门面板要不要并进来。我的建议是保留为独立 SPA、不进控制台导航， 由左上角身份切换器直接跳转；这样业务同学永远看不到管理菜单。 ② 「审批中心」是否接受从一级菜单降级到工作台待办条。 如果贵司审批是日常高频（每天十几单），建议在侧边栏保留一个带红点的「待办」项作为入口， 但工作台仍然要首屏露出。
