# 定制轨（custom/dsh-rq → RQ-DSH）功能冻结公告

> 公告日期：2026-10-13 ｜ 依据：《重构方案-对照paperclip-20261013.md》§四.2 与 §五 阶段 0
> 冻结窗口：**2026-10-13 起，至阶段 4 正式同步完成**（预计 2026-12-01 前后，见方案 §五）

## 一、冻结范围

榕器全局重构（REFACTOR-2026-10-13）期间，定制轨进入**功能冻结**：

1. **不再从上游宿主轨（本仓 main → refactor/paperclip-alignment）向 RQ-DSH push 新功能版本**；
2. RQ-DSH 备份仓（github.com/01men/RQ-DSH）维持**只 fetch 不 push** 的既有方向不变；
3. `@ybkk/gate-01` 在冻结期内**不发布新版本**（v1.2.1 为冻结基线版）。

## 二、定制轨现状底册（冻结起点事实）

- 本仓（ybkkasi / 宿主轨）当前**不存在** `custom/dsh-rq` 分支；定制轨最新状态以 RQ-DSH 备份仓 main 为准（提交 `a7f35a4`，2026-09-24，定制轨全量备份汇总提交）。
- 经文件级比对，定制轨相对上游的落地差异集中在（与方案 §四.2「差异集中在 patch 与配置层」一致）：
  - `package.json`（dsh.bundle.patch / dsh.compatibility 等定制配置）；
  - `cordis.patch.yml`（mountPath `/gate01`、品牌定制）；
  - `packages/platform-core/scenegraphs/*.json`（定制场景数据资产：jb01/jb02/qb02…qc01/sh01/sj01 等）。
- 业务代码（packages/*/src）无散入差异。

## 四、冻结期纪律

- 定制轨若发现缺陷需紧急处置：只允许在定制轨工作副本打补丁、**不合入上游重构分支**，并在下一次同步演练中一并消化；
- 上游重构若搬动 `cordis.patch.yml` / `package.json` dsh 字段 / scenegraphs 相关文件，必须在阶段报告中登记（同步演练会即时暴露漂移）；
- dsh 契约保持清单（方案 §四.1）在每阶段出口逐项打钩，任何一项不满足即阻塞阶段出口。
