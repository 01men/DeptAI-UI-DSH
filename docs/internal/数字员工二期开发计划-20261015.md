## 3. 近期工作包（W1—W7）

### W1 MCP 工具可信风险登记流程（V11 根治）

- **蓝本依据**：§4.2 第 3/4 条、V11。
- **目标**：远端 `tools/list` 发现的工具不再默认按 read 开放；写能力必须经「风险登记 → 审核 → 生效」。
- **施工要点**：
  - plugin-mcp：工具风险从「同步时隐式映射」改为显式登记数据（服务+工具粒度：risk / 登记人 / 审批引用 / 生效版本）；未登记工具一律 `unknown`；
  - 闸门语义：`facts.risk` 读取登记值；未登记工具一律拒绝写动作（TOOL_NOT_GRANTED 或新增 RISK_UNREGISTERED 语义），read 动作可按只读约束放行；
  - 管理端点（risk 登记/审批/清单）+ manifest/permissions 同步；存量已按 read 放行的远端工具出**重审清单**。
- **依赖**：无（可立即开工）。
- **并行组建议**：网关组（mcp）+ 审批面复用 skillhub 既有两级审批形态（待裁决 D-①）。
- **验收标准**：未登记写工具调用被拒且落账；登记+审批后按登记风险放行；存量重审清单产出；V11 通过；drill 补 ≥2 断言；selftest 补 ≥1 断言。
- **证据要求**：登记→审批→放行/拒绝的端到端调用记录、重审清单、审计留痕。

### W2 REST `/api/mcp/invoke` workRef 透传

- **蓝本依据**：§2.3（四入口等价约束）、组4 验收报告遗留第 6 条。
- **目标**：REST 面受管调用与平台 MCP 面同凭证同约束（permit/run/step 索引可用）。
- **施工要点**：plugin-console routes/mcp.ts 请求体增可选 `work` 索引（permitId/runId/stepKey，§10.4 仅索引非授权事实），透传 registry.invoke 第 5 形参；身份仍一律令牌解析。
- **依赖**：无。
- **并行组建议**：接入组（console）。
- **验收标准**：同一机器凭证经 REST 与 /mcp 两面调用行为一致（V01 完整态）；selftest 补 ≥1 断言。

### W3 Panel REST `/api/panel/:dept/skill-invoke` 透传 skillLoad

- **蓝本依据**：D09/V12（加载证据化）。
- **目标**：REST 响应与工具路径同构，携带 skillLoad{skillId, version, contentHash}。
- **施工要点**：路由层返回对象补透传（service 层已带，勿重复实现）。
- **验收标准**：REST 响应含 skillLoad 且与 skillHub 发布版本一致。

### W4 `/api/usage/feedback` X-On-Behalf-User 白名单收敛

- **蓝本依据**：§10.5（内部动作分类）、组6 验收报告遗留第 3 条。
- **目标**：机器主体不得归因到任意用户；仅绑定用户白名单（员工主管/绑定真人）可代报。
- **施工要点**：ops.ts feedback 路由加白名单校验；白名单外 403 + `audit.authz.denied`；既有零价快照口径不变。
- **验收标准**：白名单外归因被拒且留痕；白名单内行为不变；selftest 补 ≥1 断言。

### W5 workforce.admin 运维面落地

- **蓝本依据**：§13.1、附录 A 决策 #5。
- **目标**：消灭「预留权限点无代码引用」存量提示，补齐运营治理面。
- **施工要点（建议最小集全做）**：
  1. 批量停职/复岗（含联动撤 permit/租约，复用一期停职链路）；
  2. 任用审计报表（版本/授权/permit/调用历史穿透查询）；
  3. 过期 permit 与终态 run 台账清理任务。
- **依赖**：无。
- **并行组建议**：员工域组。
- **验收标准**：全部端点 workforce.admin 把守；非 admin 403；selftest 补 ≥2 断言；lint 提示销账。

### W7 T08 灰度交付包

- **蓝本依据**：§14 T08、§15.2 验证层次、§16 首条施工链、附录 C。
