## 0. M0 フレーミング（最初にお読みください）

**M0 レッドライン（2026-09-09 以降の全社方針）**：本プラットフォームには**金額決済セマンティクスが一切ありません**。
従量課金・転売・収益配分・ウォレット・チャージ・清算はすべて廃止され、旧サブシステム（plugin-billing）は
アーカイブ封印済みです。対外提示は次の 2 点のみです：

1. **利用量の透明な計測**（transparent usage metering）— 何が・どれだけ使われたかの事実を全員に見せる。
2. **内部コスト透過**（internal cost pass-through）— 内部調達コスト参考値としての原価のみを提示する
   （対外請求額ではありません）。

ビジネスモデルは「**チーム＋ドメイン資産**」の価格設定（業界グラフパック／シーンパック等）であり、
製造業の顧客はオンプレミス（プライベート）導入のプロジェクト制も選択できます。これらはプラットフォーム外の
契約事項であり、本プラットフォーム内部に金銭の授受は発生しません。

## 1. J4 契約：利用量レポートのデータ口径 v1（凍結稿）

- 凍結日：2026-09-09 ｜ 実装アンカー：`packages/plugin-usage/src/index.ts` の `UsageService.monthlyReport()`、
  コンソールエンドポイント `GET /api/usage/report/monthly`
- 変更規律：本契約の升版にはリリースノートの発行と両側の同期が必要です（レッドライン 1）。

### 1.1 データソースとイベント口径

- 唯一のデータソースは usage 計量イベントの流れ（`usage_events`、SQLite `data/txnstore.db`）で、
  **金額台帳は一切読みません**（billing は廃止封印済み）。
- イベント窓：`occurred_at`（ISO UTC）が `[当月 1 日 00:00, 翌月 1 日 00:00)` に落ちるイベント。
  月パラメータ形式は `YYYY-MM`。
- 冪等：イベントは `idempotency_key` でエンジン級一意。重複配信は二重計上されません。
  レポート口径は記帳口径と同一で、`POST /api/usage/reconcile` で照合（外部システム照合）できます。

### 1.2 tokens の三軸集計（J4 の中核）

tokens はイベント `meters[]` のうち**計量キー名に `tokens` を含む値の合計**です
（`tokens`／`input_tokens`／`output_tokens` をカバーし、同一イベントの複数キーは累加。
`calls` 等の非 tokens メーターは含まない）。凍結された三軸：

| 軸 | 分類フィールド | 説明 |
|---|---|---|
| 部門 byOrg | `org`（**部門の帰属フィールド**） | 全イベントが org を持つ。組織帰属のないイベントは `t_default` テナント下の空文字 org に帰属し、どの部門にも計上されない |
| Agent byAgent | `subject` のうち接頭辞 `agent:` | on-behalf-of の終点が Agent のイベント（Agent がゲートウェイ／接続器経由で消費した分を含む） |
| Skill bySkill | `resource` のうち接頭辞 `skill:` | スキル呼び出し・ダウンロードの遡及記録イベント |

付加軸（additive。コスト透過のため。J4 の凍結面には含まない）：`byModel`（`resource` の接頭辞 `model:`）。

各行の出力：`dimension / events / tokens / charge_cents / cost_cents / nonbillable_events`。

### 1.3 金額口径（M0-3 収束後）

- `charge_cents`：**ゼロ価格スナップショットで常に 0**。価格簿の list 側は統一ゼロ価格で、
  レポートは一切の対外決済金額を表示しません。価格簿に調価能力は残りますが、これは将来の運営判断専用で、
  調価時には先に契約を升版しなければなりません。
- `cost_cents`：**内部調達コスト参考値**（価格簿 cost 側 × 実測メーター値の換算）。内部コスト透過専用で、
  対外には請求書として提示してはなりません。
- `nonbillable_events`：零率規則（list=cost=0）に該当するゼロ価格スナップショットイベント数
  （`rate.nonbillable=true`）。観測系イベント（フィードバック／ナレッジパック／パネル等）はここに計上され、
  コスト口径を汚染しません。

### 1.4 提供契約（コンソールエンドポイント）

- `GET /api/usage/report/monthly?month=YYYY-MM` → JSON（権限点 `usage.read`）：
  `{ month, from, to, totals, byOrg[], byAgent[], bySkill[], byModel[] }`
- `GET /api/usage/report/monthly?month=YYYY-MM&format=csv` → CSV ファイルダウンロード
  （**UTF-8 BOM 付き**で Excel がそのまま開けます）。列：
  `维度,维度值,事件数,tokens,charge_cents(零价快照恒0),cost_cents(内部成本参考),nonbillable事件数`。
  行のグループ順：total → org → agent → skill → model。
  **企業の管理者は `usage.read` 権限で自助エクスポートできます**（M0-3 の検収口径）。

## 2. FinOps レポート v1（CFO ビュー・2026-09-16 M2 で提供）

| エンドポイント | 権限 | 説明 |
|---|---|---|
| `GET /api/finops/overview?month=YYYY-MM&window=分` | usage.read | 一括取得：コスト透過＋アイドル稼働検出 |
| `GET /api/finops/idle?month=YYYY-MM&window=分` | usage.read | アイドル稼働検出の独立照会（窓は 1〜1440 分で調整可） |
| `GET /api/finops/report/monthly?month=YYYY-MM[&format=csv]` | usage.read | CFO コストレポート。CSV は Excel フレンドリーな UTF-8 BOM 付き |

- **コスト透過（costPenetration）**：月次窓内の**部門（org）× モデル（model）のコスト交叉マトリクス**
  （Top8×Top8＋「その他」行・列。合計は常に model 域の全口径コストと一致）、**前月比**
  （前月 0 かつ当月 >0 の場合は `delta_pct=null` — 無理な百分率を作りません）、**Top 10 消費主体**、
  部門行ごとの Top3 モデル内訳。金額口径は J4 と同一（内部コスト参考 `cost_cents`、`charge_cents` は
  ゼロ価格スナップショットで常に 0）。
- **アイドル稼働検出 v1（idleAnalysis）**：
  - **これは近似ヒューリスティックであり、要人工確認です。** 判定式は「モデル呼び出し後 N 分
    （既定 30 分）内に同一主体の非モデル資源アクションがなく、同 `trace_id` の関連アクションもない」
    場合を「疑似アイドル」とする近似口径です。
  - 出力：アイドルイベント数・コスト・tokens、モデル別・部門別の内訳、人工確認用の直近 20 件サンプル。
  - 既知の誤報（純対話）がある点は**ページ上に「近似口径・要人工確認・考核には使用しない」と明示表示**されます。
    精確口径は将来の証拠エンジン（task_success／task_fail の結果返送）での置換が予定されており、
    現時点ではロードマップ項目です。
- **SPA「財務ビュー（财务视图）」ページ**（`#/finops`、治理と運営の二分区、`usage.read` で可視）：
  指標カード（当月コスト＋前月比／計量イベント数／アイドルコスト／参加軸）、部門透過表、モデルコスト順位、
  交叉ヒートマトリクス、アイドル確認サンプルの折りたたみ表、ワンクリック CSV エクスポート、月切替、
  親切な空状態。同ページからモデルカタログ管理面（`modelgw.read`／`modelgw.admin` 門控）にも入れます。
- 1DAU あたりコスト：資産運用（资产运营）ページのコスト透過表で、アプリ資産は窓 DAU から派生します
  （`GET /api/assets/benefit`）。

## 3. ゼロ価格スナップショットの姿勢

- **`charge` は常に 0**：すべての計量レポート・API 応答で `charge_cents` は恒等的に 0 です。
  これは一時的な非表示ではなく、M0 以降の**設計上の恒久方針**です。決済・請求・返金・残高の
  セマンティクスに対応する API／権限点／イベントは削除済みです（旧 `billing.*` 権限点は解析時に無視されます）。
- **決済セマンティクスなし**：ウォレット／チャージ／清算／収益配分の概念は本ドキュメント・プラットフォームの
  いずれにも存在しません。利用者の予算管理は「予算サーキットブレーカー」（org／モデル／プラットフォーム級の
  block 熔断）として、**金額ではなく内部コスト参考値の閾値運用**として実装されています。
- **価格簿（プライスブック）**：list 側ゼロ価格スナップショット＋cost 側内部調達コスト参考値。
  meter key（例：`mcp:*` は `tokens`、`model:*` は `output_tokens`）は価格簿と一致する必要があり、
  不一致の利用報告はハード拒否され、エラーに期待キーが表示されます（サイレントな漏れ計上を防ぐ設計）。

## 4. データ保持（`USAGE_RETENTION_DAYS`）

- **既定 730 日保持**（2026-09-11 最適化批次で導入）。`USAGE_RETENTION_DAYS` 環境変数で調整でき、
  **`0` は永久保持**です。
- 動作：起動 20 秒後に初回実行、以後 6 時間ごとに窓外イベントを清掃します（消費水位と対応する
  デッドレターも連動削除）。
- **セマンティクス**：イベントが清掃された後、同一冪等キーで再報告された場合は新規イベントとして
  再計上されます（**保持窓＝削除契約**）。J4 月次レポート窓（直近 13 か月）はこの保持ポリシーの影響を受けません。
- **運用の手動パージ手順**：

```bash
# usage.admin 権限の Bearer トークンで実行。body.days で一時的に窓を短縮可能（0 はスキップ＝通常ポリシーどおり）
curl -X POST localhost:7300/api/usage/retention/purge \
     -H "authorization: Bearer <token>" -H 'content-type: application/json' \
     -d '{"days": 365}'
```

  長期レポートが必要な企業は、CSV の自助エクスポート（§1.4・§2）を月次の外部アーカイブ運用と
  組み合わせてください。プラットフォーム側での超長期保持は `0`（永久）とするか、
  エクスポート済み CSV で代替します。

## 5. 経営層向けサマリ（CFO 視点の読み方）

1. **見えるもの**：部門 × モデルのコスト交叉マトリクス、前月比、Top 消費主体、1DAU あたりコスト、
   疑似アイドル稼働の候補とそのコスト影響。
2. **見えないもの（正直な境界）**：対外請求金額（存在しない）、精確なアイドル判定（v1 は近似・要人工確認）、
   TTFT テレメトリ（チャネル遥測では `ttftMs=null` で正直に未収録 — ストリーミングチャネル待ち）。
3. **意思決定への使い方**：「チーム＋ドメイン資産」のライセンス契約・領域資産パックの選定は
   本レポートの消費分布を参考に、プラットフォーム外の契約プロセスで行います。
   予算超過時は Agent の連動凍結＋L4 解凍承認（[user-guide.md](user-guide.md) §14.6）で
   消費が自動的に抑制されます。
