## 一、结论（TL;DR）

> **协作主干是真的，但治理面有一处可被利用的越权（P0），且控制台只落了 22% 的新能力。主体能力可放行，P0 必须在上线前修复。**

- 用户核心关切逐条回答：
  1. **前后端功能是否完整适配？** —— **主体适配完整，治理面不完整**。前端 374 个 API 调用点对 458 条后端路由，方法错配 0、孤儿页面 0、悬空请求 0（A 组）；A2A/UHP 后端 105 条断言 100 通过，八态生命周期、协商矩阵 16 格、治理五项、计量审计闭环均实测成立（D 组）。**但两个新插件共 28 个端点里有 22 个在控制台没有任何入口**，前端只接了 6 个（C 组）。
  2. **是否存在前端功能展示不全？** —— **存在，且是本轮最大的体验缺口**。后端 27 个 A2A/UHP 端点仅 6 个有 UI 入口（22%）；`plugin-uhp` **9 条端点前端 0 覆盖**（`grep /api/uhp` 全前端零命中），`uhp.read` / `uhp.admin` 两个权限点在控制台**形同虚设**；`a2a.admin` 同样——审批规则增删查改与立即巡检全无入口，`.page-actions` 是空容器；本轮 C4 主打端点 `GET /api/usage/collaborations` 已在 `manifest/api.yaml` 登记且实测 200 有数据，前端**零引用**。另有 `a2a.js` 三语覆盖仅 22%（153 条面向用户文案中 en-US 与 ja-JP **各缺 119 条**）。
  3. **是否存在后端功能缺失？** —— **没有发现**。后端 21 端点 × 6 账号实测零 404/405，前端请求的 6 个端点全部命中且字段名逐一对得上，权限矩阵与角色声明 100% 吻合。缺口全在**展示层**，不在**实现层**。
  4. **多层级多角色验证？** —— **做了，且发现了真问题**。9 账号（5 层级 × 3 组织）× 4 机器凭证，**902 次权限/行为判定**。权限点**声明面本身干净**（358 次门禁判定 0 误放行 0 误拒，108 次异常令牌 + 31 次自然过期令牌零 5xx、零放行）；但**声明之后的归属校验全面失守**——治理视图的只读点被实现成了跨组织、跨主体、无归属的万能权限。
  5. **Agent 层面完整验证？** —— **做了**。写了一个零平台 SDK 的独立外部 Agent 客户端（纯 node fetch），只靠 Agent Card 跑通发现→派活→轮询→SSE→列举→流式→取消；A3 协商的「要约→评估→还价→回应→轮次超限拒绝」四轮握手真实发生并成链留痕。治理门禁、凭据轮换、计量审计、交付验收全部实测通过。

| 编号 | 域 | 缺陷 | 证据 | 来源 |

| **Q-1** | A2A / UHP 协作执行面 | **`uhp.invoke` 机器凭证可劫持任意 A2A 任务，绕过人在环审批、伪造交付物，并把审计栽赃给无辜发起人**。`POST /v1/uhp/responses` 把请求体里的 `metadata.ybk_a2a_task_id` **原样当作可信任务归属凭据**传给 `createResponse({ taskId })`（`packages/plugin-uhp/src/index.ts:611-632`），执行完成后经 `emitProgress(record.taskId)` 推 `a2a.task.progress`（同文件 `:451-464`），而 A2A 侧 `onProgress()`（`packages/plugin-a2a/src/index.ts:722-749`）**只按 taskId 查任务并 transition，不校验来源归属** | **QA Lead 独立二次复现**：受害任务 `task_mvgjb0s077d1yp0s` 处于 `auth_required`（A1 目标 → `execute_confirm` → 人在环审批等待中），攻击者为**现场新建的 `scopes=['uhp.invoke']` 外部机器凭证**（无任何 A2A 权限、非发起方、跨组织），注入后受害任务被强行推进为 `completed`，`attempts=0`（从未走过 A2A 派发链路），审批工单 `apr_mvgjb0s077d4pnp8` 仍挂载但已失效 | 组B-1（B 组实测 + 附录 `p0.mjs` / `results-p0.json`）<br>**QA Lead 独立复核** |

**Q-1 的三个叠加面**（必须一起修，只修一层不闭环）：

| 面 | 表现 | 根因位置 |
|---|---|---|
| ① 审批绕过 | `auth_required` 任务被外部凭证直接推到 `completed` | `plugin-uhp/src/index.ts:611-632` + `plugin-a2a/src/index.ts:722-749` |

## 五、关键正面结论（实测证据支撑）

1. **协议主干真实可用**：独立外部 Agent 客户端（零平台 SDK，纯 node fetch）**只靠 Agent Card** 即跑通「发现 → 派活 → 轮询 → SSE → 列举 → 流式 → 取消」；Agent Card 的 Ed25519 签名可**独立验签通过**，篡改 `card.url` 后验签失败。
2. **A3 协商引擎不是摆设**：要约 → 被调方评估 → **还价** → 调用方回应 → 轮次超限拒绝，四轮握手真实发生，`history[]` 双向 offer 记录成链。
3. **权限点声明面干净**：358 次门禁判定 **0 误放行 0 误拒**；108 次异常令牌 + 31 次**自然过期令牌**判定，**零 5xx、零放行**；越权原语（请求级 `tools` / `metadata.tools`）4 类注入全部「接受但不生效 + 记入 `metadata.ignored_fields`」。
4. **治理五项拦得住**：密级天花板越级、非 online 目标、冻结目标、预算熔断、敏感规则命中，逐一实测生效并留痕；A2A 计量事件以 `resource=agent:<id>`、非计费、`calls=1` 正确落账。
5. **八态生命周期齐备**：八态全部可达（`submitted` 仅瞬态，代码 + 全量扫描佐证），`history[]` 状态迁移成链。
6. **前端无悬空请求**：前端请求的 6 个端点全部命中，字段名逐一对得上，22 个 hash 全页面冒烟**零 JS 报错**。
7. **凭据轮换语义正确**：轮换后 clientId 不变、旧 secret 立即失效、存量令牌吊销，A2A 场景下实测一致。
