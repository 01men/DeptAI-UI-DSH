# 製品紹介 — YuanBingKe（ybkk-AIOS）

## 0. 30 秒サマリー

- **6 種類の AI 資産**（MCP サービス／スキル／エージェント／AI アプリケーション／モデルルート／
  NAS ファイルストレージ）を、一套の ID・権限・利用量計測・監査で統合管理します。
- アーキテクチャは dsh の**「すべてはプラグイン」**（25 個のプラグインエントリ、独立した起動・停止）。
- **セルフホスト**が基本形。製造業のお客様はオンプレミス（プライベート）導入のプロジェクト制も選択できます。
- **決済セマンティクスなし**: ゼロ価格スナップショット＋内部コスト透過により、利用実態だけを透明化します。
- プラットフォーム自体が **MCP サーバー**として動作し、40 以上の運用ツールを任意の MCP クライアントに開放します。
- ランタイム UI は 2026-10-16 リリースより言語切替に対応しました（簡体字中国語〔既定〕／英語 en-US／日本語。第 8 節）。

## 2. 解決する課題

企業が生成 AI を業務に導入する過程で、リソースは次のように分断されがちです。

- **リソースの分断**: MCP サービス、Skill、Agent、AI アプリ、モデル経路、NAS ファイルが
  部門やツールごとにバラバラに管理され、何がどこで使われているか把握できない。
- **統一 ID・権限の欠如**: アセットごとにアカウントと権限の仕組みが乱立し、
  退出者の権限残存や越権アクセスのリスクが生じる。
- **統一計測の欠如**: 誰が・どの資産を・どれだけ使ったかの記録がなく、利用量と内部コストが見えない。
- **統一監査の欠如**: 重要なライフサイクル操作（公開・停止・取り下げ）に承認と監査証跡がなく、
  内部統制や監査対応の負担が大きい。

## 3. ソリューションの概要

YuanBingKe は、6 種類の AI 資産を 1 つのプラットフォームに統合管理するエンタープライズ AI リソース管理
プラットフォームです。セルフホストで動作し、dsh（DeepSeek Harness）と共通の
「すべてはプラグイン」アーキテクチャを採用しています。

- **一套の ID・権限**: 組織ツリー・ロール・パーミッションポイント（権限ポイント）マトリクスにより、
  すべてのアセットと操作に統一的な認可を適用します（ID・アクセス管理（IAM））。
- **一套の認証**: OIDC Provider（SSO）により、社内 AI アプリの公開前に行う ID の管理下への統合と
  DingTalk パスワードレスログインを提供します（統合認証）。
- **一套の計測**: すべての呼び出しを冪等な計測パイプラインに記録し、利用量レポートと内部コスト透過を
  提供します（利用量の透明な計測）。
- **一套の監査**: 4 種類の監査ログと L4 強制承認により、重要操作は必ず承認と監査証跡を残します。

## 4. 6 種類のアセット

YuanBingKe が統合管理する 6 種類のアセットを、平易に説明します。

### 4.1 MCP サービス（MCP デプロイサービス）

企業内のツールやデータソースを MCP（Model Context Protocol）サービスとして登録し、
ドラフト→検証→カナリア→全量リリースの段階を踏んで安全に公開します。リリース後のバージョンは
不変（イミュータブル）で、問題発生時はワンクリックロールバックできます。トークンゲートウェイが
呼び出しの権限・レート・遮断（サーキットブレーキング）を一括管理します。

### 4.2 スキル（Skill）

AI に与える手順書・知識のパッケージです。スキルマーケットに提出すると静的スキャン
（悪意あるコードや秘密鍵の漏えいを自動却下）と二段階承認を経て、バージョン管理された形で公開されます。
契約は Ed25519 署名検証で保護され、インストールパッケージは NAS に直送できます。

### 4.3 エージェント（Agent）

業務を実行する AI エージェントの本体（レジストリ）です。登録時にマシンクレデンシャルが発行され、
人間のユーザーとの紐付けや on-behalf-of トークンチェーン（代理実行）により、「誰のために・誰が」を
監査可能な形で実行します。自律レベル（A0–A3）の段階設定と、エージェント間の A2A 指名呼び出しに対応します。

### 4.4 AI アプリケーション（AI 应用）

社内で開発される AI アプリの本体（レジストリ）です。オーケストレーショントポロジを 1 枚の図で把握でき、
PV/UV/DAU の指標を、アプリからの自発報告と公開計測ビーコンの両面で収集します。OIDC SSO によるアプリ公開ゲートで、
ID の統合を完了したアプリだけが公開されます。

### 4.5 モデルルート（模型路由）

大規模言語モデルへのアクセスを、モデルアクセスゲートウェイ（modelgw）経由に集約します。
OpenAI 互換の実転送で、実測された input/output トークンを計測。チャネルガバナンスとして
フォールバックチェーン・予算サーキットブレーカーを備え、TTFT テレメトリは未収録であることを
正直に明示します（TTFT テレメトリの正直な未収録）。

### 4.6 NAS ファイルストレージ

既存の NAS（Synology 等）を「MCP ファイルゲートウェイ」経由で資産として取り込み・管理します
（NAS 資産の取り込み・管理）。組織位置＋ロール階層のデータ権限（デフォルト拒否・全経過記録）、
署名付きダウンロード URL、ファイル所有権トラッキングを提供し、DSM 非公開 API への直接アクセスは行いません。

## 5. 差別化要因

### 5.1 「すべてはプラグイン」

プラットフォーム全体が一棵のプラグインツリー（cordis フレームワーク）で構成され、各業務ドメインは
依存・権限・イベントを独立宣言した 25 個のプラグインエントリとして動作します。プラグイン単位の
独立した起動・停止が可能で、同一コードを独立ホストと dsh ホストの両方で実行できます。詳細は
[dsh-ecosystem.md](dsh-ecosystem.md)。

### 5.2 利用量の透明化（ゼロ価格スナップショット＋内部コスト透過）

プラットフォームは金額の決済セマンティクスを一切提示しません。プライスブックは
ゼロ価格スナップショット（charge 常に 0）であり、内部調達コスト参考値のみを付与します。
これにより、部門横断の利用実態と内部コストを「会計リスクなしで」透明にできます。

### 5.3 セルフホスト／オンプレミス

データは企業境界の内側に留まります（データの所在を企業内に保つ選択肢としてのオンプレミス）。製造業をはじめ
外部送信が制限される環境では、オンプレミス（プライベート）導入のプロジェクト制を選択できます。

### 5.4 プラットフォーム自己更新

上流リポジトリの新バージョンを自動検知（既定 24 時間間隔）しつつ、**アップグレードの実行は常に
管理者が決定**します。dry-run（予行）・監査記録・権限点（`platform.update.apply`）・
リリースマニフェスト署名検証（任意）を備えます。手順は[getting-started.md](getting-started.md)。

### 5.5 あらゆる MCP クライアントに開かれた MCP サーバー表面

プラットフォーム自体が MCP サーバーとして動作し（`POST /mcp`）、40 以上の運用ツールを
ZCode／Claude／Cursor 等の任意の MCP クライアントから、既存の Bearer トークンとツール粒度の
権限点のまま利用できます。

### 5.6 誠実な実装姿勢

endpoint 未設定のモデルは呼び出しを拒否し（偽の completion を生成しない）、デモ用のトランスポート層は
明示的に `exec: demo` と標記され、SLO・計測には算入されません。計測できない項目（TTFT 等）は
「未収録」と正直に明記します。マーケティング資料でもこの姿勢を維持してください。

### 5.7 三つの入口、同一の契約

同じ操作が **REST API・CLI（dshctl）・MCP ツール**の三面で同一契約（同一権限点・同一パラメータ）で
利用できます。人間はコンソール、スクリプトは CLI、AI Agent は MCP／dsh ToolRuntime から、
それぞれ最適な経路を選べます。

## 7. 本製品に含まれないもの（M0 レッドライン）

- **決済・ウォレット・収益分配のセマンティクスはありません**。チャージ／口座残高／分配等の
  金額結算の概念は、M0（2026-09-09）で機能ごと廃止・封存されています。対外には
  「利用量の透明性＋内部コスト透過」のみを提示します。
- 本文書はホスト型クラウドサービス（SaaS）の提供・価格について記述しません。提供形態は
  セルフホスト／オンプレミス導入を基本とします（商用モデルの詳細は[README.md](README.md)「商用モデル」）。
- 日本語・英語の実行時画面は現時点で存在しません（次節）。
- SOC 2 / ISO 27001 等の認証は未取得です（ロードマップ、計画中）。

### 7.1 よくある質問

**Q1. クラウド SaaS として提供されますか？**
本資料の範囲では、セルフホスト／オンプレミス導入が基本形です。ホスト型クラウドサービスの提供に
ついては本資料では触れません（原文に基づかない主張は行いません）。

**Q2. 利用料金はどのように扱われますか？**
金額の決済は行いません。プラットフォームは利用量を計測・可視化し、内部調達コストの参考値を
付与するのみです。商用契約は「チーム＋ドメイン資産」の価格設定、または製造業向けオンプレミス
導入のプロジェクト制となります。

**Q3. 既存の MCP クライアントから直接使えますか？**
はい。`POST /mcp`（Streamable HTTP・JSON 形態）経由で、ZCode／Claude／Cursor 等のクライアントから
Bearer トークンとツール粒度の権限点のまま利用できます。

**Q4. 日本語の画面は使えますか？**
はい。2026-10-16 リリースより、実行 UI に言語切替が内蔵されました（簡体字中国語〔既定〕／英語 en-US／日本語。次節）。画面キャプチャ照会には本資料の
「日本語名（中文原文）」注記も引き続きご利用いただけます。

## 8. 画面言語について

**2026-10-16 リリースより、実行 UI（コンソール／パネル／ポータル／CLI 出力／通知・承認文案／エラー表示）に
言語切替が内蔵されました：簡体字中国語（既定）／英語（en-US）／日本語。** 画面上部のセレクターで切替、設定はブラウザに保存（`rq_lang`）。CLI は `--lang` または `DSHCTL_LANG` に従います。辞書未収録の文言は自動的に中国語にフォールバックします。
本ドキュメントは UI の場所を「日本語名（中文原文）」の二言語注記で表記しています
（例: 組織とアカウント（组织与账号））。この注記は、中国語固定運用や画面キャプチャ照合時に引き続き有効です。
