# YuanBingKe（ybkk-AIOS）· エンタープライズ AI リソース管理プラットフォーム（国際版・日本語）

YuanBingKe（製品の中国語名: 元冰可）は、**DeepSeek Harness（dsh）の「すべてはプラグイン」アーキテクチャ**上に実装された、
エンタープライズ AI リソース管理プラットフォームです。MCP サービス、スキル、エージェント、AI アプリケーション、
モデルルート、NAS ファイルストレージの **6 種類のアセット**を、**一套の ID（IAM / OIDC SSO）・一套の権限・
一套の利用量計測・一套の監査**で統合管理します。

本ページは国際読者向けに再構成した製品全体像の案内です。中文原典（リポジトリルート `README.md`）の直訳ではなく、
国際市場向けに必要な情報を整理しています。開発バッチ単位の詳細な変更履歴は「10. リリース履歴」のポインタを参照してください。

## 1. YuanBingKe とは

企業が AI を業務に取り込む際に散らかりがちなリソース――MCP サービス、Skill、Agent、AI アプリ、モデル経路、
NAS 上のファイル資産――を 1 つのプラットフォームに管理下に置き、次の 4 つを共通基盤として提供します。

- **一套の ID・権限**: 多階層の組織ツリー、ロール／ユーザーグループ、パーミッションポイント（権限ポイント）マトリクス、
  OIDC Provider による SSO、DingTalk パスワードレスログイン。
- **一套の利用量計測**: すべてのアセット呼び出しを冪等（べきとう）な計測パイプラインで記録し、
  部門／Agent／スキル等の軸で利用量レポートを提供します。
- **一套の監査**: 4 種類の監査ログ、アラートルールエンジン、L4 強制承認（公開・停止・取り下げ・失効の各ライフサイクル操作）。
- **一套のガバナンス**: シーン単位の認可（sceneCode）、監査証拠アンカー、承認センター（审批中心）・通知センター（通知中心）。

アーキテクチャは dsh ホストと共通の cordis プラグインフレームワーク（`@deepseek-ai/cordis`）上で動作し、
稼働中のプラットフォームそのものが一棵のプラグインツリーです。詳細は「4. アーキテクチャ」および
[dsh-ecosystem.md](dsh-ecosystem.md) を参照してください。

## 3. クイックスタート

最短の手順は次の 2 行です（前提: Node ≥ 22.6、ビルド手順は不要）。

```bash
npm install
npm start            # 既定で http://127.0.0.1:7300 を起動
```

デモデータを含めて評価する場合は `DEMO_SEED=1 npm start`。dsh ホストへのバンドルインストールは
`dsh plugin --profile web add github:01men/ybkkasi`（データプレーンは `/rq` プレフィックスでマウント）。

起動後の最低限の検証として、次の品質ゲートを実行できます（詳細は[getting-started.md](getting-started.md)）:

```bash
npm run selftest        # セルフテスト（隔離インスタンス、本番データに触れない）
npm run lint:manifests  # 全プラグインのマニフェスト 5 面 YAML 検証
```

評価を素早く始めたい場合は、デモモードが有用です（**本番では使用しないでください**）:

デモアカウント（`admin`／`ops`／`hr`／`dev`／`audit`、パスワードはいずれも `Ybk@2026`）と

## 4. アーキテクチャ:「すべてはプラグイン」

イベントを独立して宣言し、独立した起動・停止が可能です。

### 4.2 プラグイン協働の規律

状態変更は必ずイベントを発行し、プラグイン間の連動はイベントバスまたは拡張ポイント（`ctx.platformBus`）のみを
経由します。相手プラグインのデータへの直接アクセスは禁止されています。例: `iam.user.frozen` → authn が全トークンを失効、
`agent.offlined` → クレデンシャル失効＋紐付けユーザーへ通知、`mcp.unhealthy` → 遮断＋監査記録。

### 4.3 同一コード、複数のホスト形態

- **独立ホスト（既定）**: `node src/main.ts` で完全なプラットフォーム（コンソール＋API＋ツール）を起動。
- **完全 dsh ランタイム**: `cordis.yml` により同一のプラグイン群を `dsh web` にマウント。プラットフォーム登録の
  運用ツールが dsh ネイティブ ToolRuntime に直接入り、モデルから参照・呼び出し可能になります
  （「すべての MCP サービスと稼働状態を列挙して」→ `mcp_service_list`）。
- **単プロセス・単一入口（ホストマウント形態）**: `dsh-plugin-dsh-bridge` がデータプレーンを `/rq` プレフィックスで
  dsh webServer にマウントし、dsh web のポートが唯一の入口となります（`startHttp: false` で独立ポートを閉止）。
- **リモート dsh 接続（第 3 の形態）**: 他の端末はプラグインマーケット経由で本プラットフォームを導入し、
  1 回限りの接続コードでホストに認証。運用ツールの実行はすべてホストへリモート代理されます
  （ソースコード不要・`data/` 共有不要。権限はテンプレートで収斂、全経過を監査）。

アーキテクチャとエコシステムの詳細は [dsh-ecosystem.md](dsh-ecosystem.md) を参照してください。

### 4.4 分野別スキルハンドブック（dsh-ops）

`skills/dsh-ops-*/SKILL.md` には、分野別の運用ハンドブック（総合索引 `dsh-ops-admin` を含む 9 種）が
同梱されています。dsh のスキルシステムは既定でリポジトリ直下を走査しないため、Agent にこれらの
手册を与えるにはコピーまたはリンクを配置します:

```bash
# ユーザー単位（すべてのセッションで有効）:
cp -r skills/dsh-ops-* ~/.dsh/skills/
# またはプロジェクト単位（当該プロジェクトのみ）:
mkdir -p .dsh/skills && cp -r skills/dsh-ops-* .dsh/skills/
```



## 5. 利用量の透明化と M0 コンプライアンス姿勢

YuanBingKe は **M0 合規収束（2026-09-09）** 以降、金额の決済セマンティクスを一切提示しません。

- **廃止**: 従量課金・転売・収益分配・代行徴収。ウォレット／分配のサブシステム（plugin-billing）は一括で
  オフライン封存されました（履歴データの CSV 封存登録は `docs/billing-archive-register.md`〔中文・内部〕）。
- **対外提示は「利用量の透明性＋内部コスト透過」のみ**: プライスブックはゼロ価格スナップショット
  （charge は常に 0）＋内部調達コスト参考値。金額の決済表現は製品のどこにも現れません。
- **利用量レポート**: 月次利用量レポート（部門／Agent／スキル tokens の 3 軸集計＋CSV セルフエクスポート、J4 契約）、
  FinOps レポート v1（コスト透過・アイドル稼働検出・1DAU あたりコスト）。
- **イベント保持ポリシー**: 既定 730 日（`USAGE_RETENTION_DAYS`、0=永久）。

この姿勢は翻訳文書にも適用されます。本日本語版を含む全言語版で、課金・決済・ウォレットの語彙は
機能説明として使用しません（M0 レッドライン。GLOSSARY.md 参照）。

### 5.1 レポート面の詳細

- **J4 月次利用量レポート**: 部門／Agent／Skill tokens の 3 軸集計＋CSV セルフエクスポート
  （`GET /api/usage/report/monthly?month=YYYY-MM[&format=csv]`、権限点 `usage.read`）。
- **FinOps レポート v1**: 部門×モデルのコスト交差マトリクス、Top 消費主体、上月比、
  アイドル稼働検出（近似口径であることを画面上で明示し、人工確認を促す）、
  1DAU あたりコスト、財務ビュー（财务视图）`#/finops` ページと Excel 親和の CSV エクスポート（UTF-8 BOM）。
- 金額は常に内部調達コスト参考値（CNY 表記の参考値）であり、請求・支払の金額は表示されません。

### 5.2 安全性と堅牢性への投資（実装済みの抜粋）

- **不正アクセス対策**: ログイン・Client Credentials・SSO 紐付け・OIDC 認可すべてに失敗ロック
  （15 分窓で 5 回失敗でロック、期間は段階的に最大 24 時間、永続化により再起動回避不可、発火時にアラート）。
  パスワードは scrypt KDF ＋タイミング安全比較で保存し、旧ハッシュは初回ログイン時に透過的に移行します。
- **トークンの衛生**: refresh_token ローテーション鎖（一回一換・リプレイで全鎖失効）、
  `state` CSRF 対策＋認可コード一回消費、aud（オーディエンス）検証、機械クレデンシャル権限変更時の
  既存トークン連動失効、シークレットローテーション（旧値は即時無効・新値は 1 回のみ表示）。
- **OIDC 強度**: scope ホワイトリスト、全経路 PKCE S256、JWT の iss/aud/kid 検証、
  JWKS 鍵ローテーション（旧鍵 24 時間の検証猶予）。
- **通信と応答**: 全レスポンスにセキュリティヘッダ既定有効（CSP/nosniff/SAMEORIGIN/Referrer-Policy。
  `SECURITY_HEADERS=off` で一括解除）、`/api/*` は `cache-control: no-store`。
- **堅牢性**: 認証系データの即時 fsync 落盤、壊れた JSON 集合の自動バックアップ＋明示アラート、
  イベントバスの永続化＋リトライ／デッドレター、組織隔離の fail-closed（越権は 403）。
- **平台級署名基盤**: Ed25519 署名のプラットフォーム共通実装（リリースマニフェスト検証・改ざん防止）。

## 6. 商用モデル

商用モデルは **「チーム＋ドメイン資産」による価格設定**（2026-09-15 更新）です。

- プラットフォーム一括のパッケージ価格ではなく、**開設するチームの規模と選択したドメイン資産**
  （業界ナレッジグラフパック〔行业图谱包〕／シーンパック〔场景包〕等）に基づいて価格を設定します。
- **製造業のお客様はオンプレミス（プライベート）導入のプロジェクト制**を選択できます。データは企業境界の
  内側に留まり、セルフホスト運用が基本形です。
- 具体的な価格表の提示は本ドキュメントの範囲外です（M0 口径: 金額を文書に表示しない）。個別にお問い合わせください。
- 導入・運用の技術的要件（セルフホスト構成・自己更新運用等）は[getting-started.md](getting-started.md)と
  中文の [docs/deploy-enterprise.md](../../deploy-enterprise.md)（内部寄り）を参照してください。

> 口径の経緯: M0（2026-09-09）で従量課金・転売・収益分配が廃止され、当初は「オンプレミス年費＋
> ガバナンスパッケージ」の口径が採られました。その後 2026-09-15 に現行の**「チーム＋ドメイン資産」**
> 価格設定へ更新されています。文書間で古い表現（年費制等）を見つけた場合は、最新の README 横断banner
> （中文原典）を正としてください。

## 7. 開発者向けの入口（REST・CLI・MCP・docs）

プラットフォームの能力は 4 つの入口から同一の権限モデルで利用できます。

### 7.1 REST API（Bearer トークン）

```bash
# ログイン（token を取得）
curl -s -X POST localhost:7300/api/auth/login -H 'content-type: application/json' \
     -d '{"username":"admin","password":"<パスワード>"}'
# 全体オーバービュー
curl -s localhost:7300/api/overview -H "authorization: Bearer <token>"
# 月次利用量レポート（J4、JSON/CSV）
curl -s "localhost:7300/api/usage/report/monthly?month=2026-10" -H "authorization: Bearer <token>"
```

### 7.2 CLI（dshctl・機械可読出力対応）

```bash
node cli/dshctl.mjs mcp list --output json
node cli/dshctl.mjs nas files <id> --path=/skillhub
node cli/dshctl.mjs credential rotate <principalId>   # シークレットローテーション（旧値は即時無効）
```

### 7.3 プラットフォーム即 MCP サーバー

```bash
curl -s -X POST localhost:7300/mcp -H "authorization: Bearer <token>" -H 'content-type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

ZCode／Claude／Cursor 等の MCP クライアントから、Bearer トークン＋ツール粒度の権限点のまま
40 以上の運用ツールを直接呼び出せます。

### 7.4 `/docs` 静的公開（ホワイトリスト制）

```bash
curl -s http://localhost:7300/docs/app-sso-integration.md   # ホワイトリスト内の対外ガイド
```

対外接続ガイド等のホワイトリスト文書のみ匿名公開され、内部ドキュメント（QA 報告・開発計画・契約等）は
404 です（2026-10-15 バッチの収斂口径）。

## 9. ガバナンスと境界

### 9.1 プロトコル層の ASCII ポリシー

イベント名、パーミッションポイント、エラーコード、API エンベロープフィールド（`ok`/`data`/`error`）、
環境変数名（`DEMO_SEED`、`ADMIN_PASSWORD`、`USAGE_RETENTION_DAYS`、`SECURITY_HEADERS`、`GITHUB_TOKEN`、
`DSH_UPDATE_AUTO_CHECK` 等）、コマンド、パス、コードブロック、パッケージ名は**逐字 ASCII で保持**されます。
これらはシステム間の機械契約であり、翻訳・転写・ローカライズの対象ではありません（R10 口径）。
中文の権威ある対照表は [docs/协议键中文对照总表.md](../../协议键中文对照总表.md) を参照してください。

### 9.2 デモモードに関する警告

`DEMO_SEED=1` は評価・トレーニング専用であり、完全なデモデータと既知パスワード（`Ybk@2026`）の
デモアカウントを注入します。**本番環境では絶対に有効化しないでください。** 本番導入の既定は
ベースライン初期化（内蔵ロール＋ルート組織＋プラットフォーム管理者のみ、デモデータなし）です。

### 9.3 誠実表述ポリシー

- 本ドキュメント群は**実装済み機能のみ**を記述します。計画中の項目には必ず「ロードマップ（計画中）」を明記します。
- SOC 2 / ISO 27001 等のコンプライアンス認証は**未取得**であり、ロードマップ上の項目です。
- 性能・試験数値（selftest 1,610 件等）は「直近一回の実行時点」の値であり、履歴カウントは無効とする
  リポジトリ口径に従います。
- デモ用のモック（DingTalk モックコネクタ・`exec: demo` 伝送等）はすべて明示的に標記され、
  実機能として提示されません（9.6 節参照）。

### 9.4 画面言語について

**2026-10-16 リリースより、実行 UI（コンソール／パネル／ポータル／CLI 出力／通知・承認文案／エラー表示）に
言語切替が内蔵されました：簡体字中国語（既定）／英語（en-US）／日本語。** 画面上部のセレクターで切替、設定はブラウザに保存（`rq_lang`）。CLI は `--lang` または `DSHCTL_LANG` に従います。辞書未収録の文言は自動的に中国語にフォールバックします。
本ドキュメントでは UI の場所を「日本語名（中文原文）」の二言語注記で表記しています
（例: 組織とアカウント（组织与账号））。この注記は、中国語固定運用や画面キャプチャ照合時に引き続き有効です。
補助手段としてブラウザのページ翻訳機能も引き続き利用できます。

### 9.6 動作の境界（抜粋）

- ビジネス設定は JSON コレクション（原子落盤）、計測・利用量データは SQLite（`data/txnstore.db`、WAL＋冪等一意索引）。
- MCP 実行層は実 HTTP 伝送（`exec: real`）。`exec: demo` は明示的なデモ降格であり、計測・SLO には算入されません。
- DingTalk コネクタは実 OpenAPI（`mode: real`）と mock（健康状態に `mock: true` と明記）を区別し、
  降格データを実際の IdP 機能として提示しません。
- `/api/*` の未一致ルートへの匿名リクエストは一律 401 です（404 ではありません。ルート存在性の
  側チャネルを防ぐ設計内挙動）。
- Node ≥ 22.6 でネイティブ TypeScript 実行（ビルド手順なし）。OIDC 秘密鍵は data ディレクトリに保存され、
  本番では KMS への移行を推奨します。
